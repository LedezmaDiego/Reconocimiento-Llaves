# Notas del repositorio

- Hay dos componentes: `main.py` es el servidor FastAPI (incluye el HTML/CSS/JS de `/registro` y `/admin`); `src/main.cpp` es el firmware ESP32-CAM compilado con `platformio.ini` (entorno `esp32cam`, Arduino). `codigomain.txt` actualmente duplica el firmware, pero PlatformIO no lo compila.
- Desde la raíz, iniciar el servidor con `python main.py` (Uvicorn en `0.0.0.0:8000`, con recarga). Definir `ADMIN_CLAVE` (el valor predeterminado es inseguro), `PB_EMAIL` y `PB_PASSWORD`; `PB_URL` apunta por defecto a `http://127.0.0.1:8090`. Iniciar aparte PocketBase con un superusuario. Al arrancar, el servidor intenta crear la colección privada `personal`, pero sigue funcionando si PocketBase no responde; las operaciones de usuarios y administración sí lo necesitan. Este repositorio no incluye ejecutable ni script para iniciar PocketBase.
- `requirements.txt` está codificado en **UTF-16 LE con BOM**, no en UTF-8: tenerlo en cuenta al instalar dependencias (`pip install -r requirements.txt` podría fallar por la codificación). La aplicación usa sintaxis de Python 3.10+ y DeepFace/TensorFlow; los embeddings usan VGG-Face y el detector `yunet`.
- Comandos del firmware desde la raíz: `pio run -e esp32cam` para compilar, `pio run -e esp32cam -t upload` para cargar y `pio device monitor -b 115200` para ver el puerto serie. `src/main.cpp` contiene Wi-Fi, IP/URL del servidor e ID del casillero; ajustarlos a la red de destino sin copiar credenciales a la documentación. La placa envía JPEG sin envoltorio a `/reconocimiento` con `X-Casillero-Id` y busca literalmente `"modo":"registro"` y `"autorizado":true` en la respuesta: conservar ese formato al cambiar la API. Por ahora solo informa la autorización por el puerto serie; no llama a `/retiro` ni `/devolucion`, ni acciona una cerradura.
- El almacenamiento está dividido: PocketBase guarda usuarios, hashes de PIN y aprobaciones; `llaves.db` guarda estados e historial de casilleros; `personas_autorizadas/` contiene fotos aprobadas y `fotos_pendientes/` fotos en revisión. Al arrancar se crean los directorios y comienza un hilo de verificación de fotos. Sesiones, modo, acceso por código, última foto y caché de embeddings viven en memoria del proceso; no asumir que se comparten entre varios workers.
- No hay suite de pruebas automáticas ni configuración de lint. Comprobaciones puntuales: `python -m py_compile main.py probar_deteccion.py` (solo sintaxis, sin servicios), `python probar_deteccion.py ruta/a/foto.jpg` (comparación manual de detectores; requiere DeepFace y una foto) y `pio run -e esp32cam` para el firmware. La integración completa necesita PocketBase y una ESP32-CAM accesible.
- `llaves.db`, `pb_data/*.db` y `pws.txt` están versionados aunque `.gitignore` menciona algunos datos de ejecución. No sobrescribir, restaurar ni incluir por accidente cambios en bases de datos o credenciales; no exponer fotos reales de rostros ni contraseñas.
